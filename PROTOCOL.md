# ЛР2. Протокол: мультимодальный краткосрочный прогноз провалов спроса в метро

Протокол зафиксирован **до** запуска моделей. Отступления записываются в раздел 13 с датой и причиной.
Результаты, полученные до отступления, не удаляются.

Работа выполняется индивидуально.

## 0. Как задание ЛР2 переложено на нашу задачу

Задание сформулировано на финансовом примере: новость о компании + котировки + свечной график,
прогноз направления доходности. Мы делаем то же самое на данных ВКР (метро Нью-Йорка):

| Задание (финансы) | ЛР2 (метро) |
| --- | --- |
| текст финансовой новости | служебные оповещения MTA о сбоях, опубликованные до момента прогноза |
| тикер | станционный комплекс (через линии, которые на нём останавливаются) |
| окно OHLCV | почасовые входы станции и её соседей, календарь, погода, события |
| свечной график | изображение ряда входов за последние 48 ч на фоне той же недели неделю назад |
| направление доходности следующего дня | провал спроса на станции в ближайший час (входов < 75% обычного) |
| биржевой календарь, часовой пояс | местное время Нью-Йорка, переходы на летнее время, праздники |
| применение к отрасли ВКР (задание 4) | лучшая схема на отложенном периоде, на всей сети из 424 станций |

**Почему краткосрочный прогноз, а не на сутки.** Набор оповещений почти целиком состоит из сообщений
о происшествиях в реальном времени (задержки, пропуск станций, объезды), а не из анонсов плановых
работ: по выборке из 2 000 строк планов ~3%. О завтрашнем сбое сегодня оповещения нет, поэтому прогноз
на сутки текстовой модальности не получает. Прогноз на ближайший час использует оповещения по прямому
назначению и соответствует слову «динамического» в теме ВКР: прогноз обновляется по свежей информации
в течение дня.

**Связь с ВКР.** Если текст даст прирост, признаки оповещений войдут в модель ВКР как ковариаты
режима «уточнение прогноза в течение дня». Если не даст, это отрицательный результат для главы 3.

## 1. Постановка

- **Объект** `o = (s, T)`: станционный комплекс `s` и момент прогноза `T` (начало часа, местное время).
  `T` — каждый час с 06:00 по 23:00.
- **Цель:** провал спроса в часе `[T, T+1)`:
  `drop = 1`, если `y(s, T) < 0,75 · ref(s, T)`.
  - `ref(s, T)` — медиана входов в тот же час той же недели за 4 предыдущие недели
    (`T − 168k`, `k = 1…4`), только по открытым станционным дням.
- **Горизонт:** основной `h = 1` (час, начинающийся в `T`). Чувствительность: `h = 2, 3`
  (часы `[T+1, T+2)` и `[T+2, T+3)`, информация та же, до `T`).
- **Допущение A1.** Входы за прошедший час известны в момент `T`. У MTA учёт проходов идёт в реальном
  времени; открытый набор публикуется с задержкой, но для диспетчерской задачи допущение реалистично.
  Записывается в ограничения.

**Исключаются из выборки** (каждое исключение пишется в `excluded.csv` с причиной):
- станционный день закрыт (`closed_wide`; маска только для исключения, не признак);
- `ref < 50` входов (шум малых чисел) или меньше 2 открытых недель для `ref`;
- сдвоенный час осеннего перевода времени и соседние часы;
- дни с провалом в выгрузке оповещений (правило S8);
- даты после конца оповещений (11.08.2026).

## 2. Модальности и схема объекта

| Модальность | Что входит | Когда известно |
| --- | --- | --- |
| **числа** | входы `y(T−1…T−24)` и `y(T−168)` в долях от `ref`; отношение последних 1 и 3 ч к обычному; то же отношение, усреднённое по соседям по линии (`adj_line`) за последний час; `ref`; календарь (час, день недели, праздник, школьный день); погода, наблюдённая в `T−1` (температура, осадки, снег); события на площадках; признаки станции (масштаб, кластер, район, число линий, CBD) | всё строго до `T`, календарь и расписание событий — заранее |
| **текст** | активные на момент `T` эпизоды оповещений по линиям станции (правила S4–S7): до 5 штук, сначала те, где станция упомянута, затем по свежести; в каждом — сколько минут назад, тип (`status_label`) и `header`. Если активных нет — модальность отсутствует. Из того же текста — структурные признаки: число активных, число по типам, минут с последнего, станция упомянута, станция внутри участка «from X to Y / between X and Y», упомянута соседняя станция (≤ 2 перегонов), направление | `date` оповещения `< T` |
| **изображение** | PNG 336 × 224: входы станции за последние 48 ч (сплошная линия) и те же 48 ч неделю назад (пунктир), вертикальная черта в `T`, минимальные подписи осей | только часы `< T` |

Схема объекта сохраняется в `results/lab00/data_schema.md`, пример объекта — в `object_example.json` и `.png`.

   - провалы выгрузки.

## 4. Правила временной синхронизации

| № | Правило |
| --- | --- |
| S1 | Оба набора — местное время Нью-Йорка без часового пояса (floating timestamp Socrata). Время не конвертируется. **Проверка:** взаимная корреляция «оповещение о пропуске станций или приостановке → провал на этой станции» по сдвигам −3…+3 ч; максимум ожидается на сдвиге 0 или +1. Если он на другом сдвиге — это отступление, сдвиг исправляется. |
| S2 | Переходы на летнее время: часы 00:00–03:00 в дни перевода не используются (а 06–23 не затронуты). Весенний несуществующий час отсутствует в обоих наборах. |
| S3 | Дубликаты: повтор `alert_id` удаляется; повтор `(event_id, update_number)` — остаётся первый; подряд идущие одинаковые `header` внутри события схлопываются. |
| S4 | **Состояние «на момент T».** Для события используются только обновления с `date < T`. Событие активно, если последнее такое обновление не является сообщением о восстановлении (`resumed`, `restored`, `regular service`, `running normally` и т.п.) и прошло не больше 90 мин (для `suspended`, `part-suspended`, `reroute`, `stops-skipped` — 180 мин). Обновления с `date ≥ T` не используются никогда, в том числе для определения конца эпизода. |
| S5 | Линии: `affected` делится по `\|`; линии станции берутся из скобок в названии комплекса. Челноки (S, FS, GS, H) приводятся к единому словарю. Станция затронута, если пересечение линий непусто. |
| S6 | Упоминание станции: названия после `at / near / from / to / between / and` сопоставляются с псевдонимами комплексов (части названия до и после `/`) **с ограничением по линии** оповещения. Неоднозначное сопоставление считается непривязанным и пишется в журнал. |
| S7 | Участок «from X to Y» / «between X and Y»: станции на кратчайшем пути X → Y по графу `adj_line`, ограниченном станциями этой линии. |
| S8 | Провалы выгрузки: день, где оповещений метро < 25% скользящей медианы за 28 дней, помечается и исключается из сравнения (видно уже: ноябрь 2024). Оценка заканчивается 11.08.2026 — концом набора оповещений. |
| S9 | Изображение строится только по часам `< T`; автоматическая проверка: последняя точка графика `< T`, доля пустых (все нули) и совпадающих по хэшу изображений. |
| S10 | Погода — наблюдённая в `T−1`, а не прогноз: для прогноза на час вперёд текущая погода известна. |

## 5. Разбиение и выборки

| Часть | Период | Объекты | Назначение |
| --- | --- | --- | --- |
| train | 01.01.2023 – 31.03.2026 (как в ВКР) | все объекты с активным оповещением о пропуске, приостановке или объезде по линиям станции + 10% остальных, веса `1/p` | обучение |
| val | 01.04 – 31.05.2026 | 50% случайных объектов, естественное распределение | гиперпараметры, ранняя остановка, порог, стекинг |
| test | 01.06 – 15.07.2026 | все объекты | сравнение моделей (задание 3) |
| holdout | 16.07 – 11.08.2026 | все объекты, 424 станции | отложенный период, применение лучшей (задание 4) |
| E-1200 | из test | 1 200 объектов: 3 слоя по 400 — (а) станция упомянута в активном оповещении о пропуске / приостановке / объезде или лежит на участке, (б) по линиям только задержки, (в) активных оповещений нет; `seed = 42` | общая выборка для всех моделей, включая VLM |
| V-60 | из val | 60 объектов по той же схеме | отладка промптов VLM |

Разбиение строго по времени. Контекст объекта может заходить в предыдущую часть: это прошлое,
утечки нет. Метрики считаются отдельно на test (обучаемые модели, естественное распределение)
и на E-1200 (все модели, обогащённая выборка: на ней сравниваются только модели между собой).

## 6. Модели

**Одномодальные baseline'ы** (обязательные по заданию):

| № | Модель | Вход |
| --- | --- | --- |
| U1 | LightGBM | только числа |
| U2 | `BAAI/bge-small-en-v1.5` (эмбеддинги, средние по активным оповещениям с весом релевантности) + структурные признаки текста → LightGBM | только текст |
| U3 | `google/siglip-base-patch16-224` (эмбеддинг изображения) → логистическая регрессия | только изображение |
| U0 | правило инерции: провал, если в `T−1` поток < 75% обычного | ориентир, не baseline задания |

**Мультимодальные модели и схемы слияния** (8):

| № | Схема | Модальности | Слияние |
| --- | --- | --- | --- |
| M1 | LightGBM: числа + структурные признаки текста | числа, текст | раннее |
| M2 | LightGBM: числа + эмбеддинги текста (PCA 32) + эмбеддинги изображения (PCA 16) | все три | раннее |
| M3 | Стекинг: логистическая регрессия на логитах U1, U2, U3 (блочная кросс-валидация по дням на val) | все три | позднее |
| M4 | Gated fusion: свой кодировщик на каждую модальность, обучаемые ворота, выпадение модальностей p = 0,2 при обучении | все три | промежуточное |
| M5 | Cross-attention: токены часов ряда (запросы) смотрят на токены оповещений и токен изображения; 2 слоя, d = 64 | все три | промежуточное, внимание |
| M6 | Qwen2.5-VL-3B-Instruct, zero-shot | текст + изображение | внутри VLM |
| M7 | Qwen2.5-VL-7B-Instruct (4 бита), zero-shot | текст + изображение | внутри VLM |
| M8 | Phi-4-multimodal-instruct, zero-shot (запасные варианты: InternVL3-2B, MiniCPM-V-2.6) | текст + изображение | внутри VLM |

**VLM.**
- Вероятность провала берётся из логитов ответа `Yes` / `No` на первом токене. Генерации нет, ответ
  не может быть невалидным. `temperature = 0`.
- Каждая VLM запускается в трёх вариантах входа, как требует задание: только текст оповещений
  (+ станция и время), только график, текст + график (основной).
- Промпты отлаживаются на V-60, на test запускаются один раз.
- Дополнительно: вероятность лучшей VLM добавляется признаком к U1. Так проверяется, несёт ли VLM
  информацию сверх чисел.

## 7. Метрики

| Группа | Метрика | Направление |
| --- | --- | --- |
| качество (основная) | PR-AUC (average precision): класс редкий, AUROC при редком классе завышает качество | больше лучше |
| качество | macro-F1 и MCC при пороге, максимизирующем macro-F1 на val; AUROC | больше лучше |
| калибровка | Brier score, ECE (15 бинов) | меньше лучше |
| прирост | ΔPR-AUC к лучшему одномодальному baseline (выбор baseline — по val) | больше лучше |
| устойчивость | PR-AUC без текста и без изображения на входе (без переобучения) / PR-AUC с полным входом | больше лучше |
| ресурсы | задержка на объект p50 / p95 (пачка 1), пропускная способность, пиковая память GPU, стоимость 1 000 прогнозов (GPU-часы × 0,35 $/ч, ориентир аренды T4) | меньше лучше |

**Статистика.**
- **Доверительные интервалы:** блочный бутстрэп по дням (все объекты одного дня — один блок:
  сбои коррелированы внутри дня), 1 000 повторов, 95%. Для разностей — парный.
- **Permutation test прироста:** внутри каждого дня с вероятностью ½ меняются местами прогнозы
  мультимодальной модели и baseline, 2 000 перестановок, односторонний p.
- **Перестановка модальности:** у обученной модели текст (или изображение) перемешивается между
  объектами того же часа. Падение качества показывает вклад этой модальности.

## 8. Гипотезы (до запусков)

- **H1.** Лучшая мультимодальная схема повышает PR-AUC относительно лучшего одномодального baseline
  на test минимум на 0,02; 95%-ный интервал не включает 0, permutation p < 0,05.
- **H2.** Прирост сосредоточен на объектах слоя (а), где оповещение говорит о пропуске, приостановке
  или объезде у этой станции. На объектах без активных оповещений прирост ≈ 0.
- **H3.** Изображение не даёт прироста сверх чисел: это другая форма тех же данных.
- **H4.** Прирост от текста убывает с горизонтом `h = 1 → 3` и со временем, прошедшим с оповещения.
- **H5.** VLM в zero-shot уступают обучаемым схемам слияния по PR-AUC, а по задержке хуже на 2–3 порядка.

## 10. Правило выбора лучшей схемы (задания 4–5)

1. **Допуск.** ΔPR-AUC к лучшему одномодальному baseline на test > 0, 95%-ный интервал не включает 0,
   permutation p < 0,05.
2. **Сводный балл** допущенных (min-max нормировка среди них, 1 = лучшая):
   - 30% — PR-AUC;
   - 15% — macro-F1;
   - 20% — AUROC;
   - 15% — Brier;
   - 10% — устойчивость (минимум по «без текста» и «без изображения»);
   - 10% — p95 задержки (в логарифме).
3. **Лучшая** — с максимальным баллом. При разнице баллов < 0,02 берётся более простая и быстрая.
4. **Подтверждение на holdout.** Выбранная схема переобучается на train + val и проверяется на holdout
   (16.07 – 11.08.2026, все 424 станции). Прирост к baseline на holdout должен сохранить знак, а 95%-ный
   интервал — не включать 0. Иначе вывод: «прирост не подтверждён на отложенном периоде».
5. **Применение (задание 4).** На holdout — метрики по районам, по типам оповещений, по часам пик; пример
   диспетчерского списка «станции с вероятным провалом в ближайший час» на одну дату.
   Если до holdout не дошла ни одна схема (п. 1), к лучшей по PR-AUC применяется то же самое с пометкой
   «прирост не доказан».

**Если нет ни одной допущенной схемы:** это результат. Задание 6 тогда отвечает, почему мультимодальность
не окупилась.

## 11. Анализ ошибок и режимы (задания 5–6)

- **Срезы:**
  - слои а / б / в;
  - тип оповещения;
  - минут с оповещения (0–15, 15–60, > 60);
  - часы пик и вне пик, будни и выходные;
  - район, квинтиль масштаба станции;
  - дождь и снег.
- **Конфликт модальностей:** текст говорит о сбое, а числа нормальные, и наоборот. Кто прав чаще.
- **10 характерных ошибок** с текстами оповещений и графиками.
